## Таблица 1. Сравнение функционального и процессного подходов к управлению

| Критерий сравнения | Функциональный подход | Процессный подход |
|---|---|---|
| Объект управления | Отдельное подразделение (отдел, кафедра) | Сквозной бизнес-процесс, проходящий через несколько подразделений |
| Ориентация | На выполнение функций внутри подразделения | На конечный результат для потребителя |
| Ответственность | Размыта между подразделениями | Закреплена за владельцем процесса |
| Координация | Через вышестоящее руководство (вертикально) | Напрямую между участниками процесса (горизонтально) |
| Скорость принятия решений | Низкая — решения проходят по иерархии | Высокая — решения принимает владелец процесса |
| Гибкость к изменениям | Низкая — структура жёсткая | Высокая — процессы легко перестраиваются |
| Дублирование функций | Часто встречается | Минимизировано |
| Оценка результатов | По показателям подразделения | По показателям процесса (KPI) |
| Прозрачность деятельности | Низкая — каждый видит только свой участок | Высокая — виден весь процесс от начала до конца |
| Мотивация персонала | За выполнение должностных обязанностей | За результат процесса |

*Составлено на основе [4, 8, 22]*

## Рисунок 1. Структура бизнес-процесса (модель IDEF0)

```
┌─────────────────────────────────────────────────────────────────┐
│                    УПРАВЛЯЮЩИЕ ВОЗДЕЙСТВИЯ                       │
│    (регламенты, стандарты, нормативные акты, ФГОС, приказы)      │
└──────────────────────────────┬──────────────────────────────────┘
                               │
                               ▼
┌──────────────┐    ┌─────────────────────────┐    ┌──────────────┐
│              │    │                         │    │              │
│    ВХОДЫ     │───▶│     БИЗНЕС-ПРОЦЕСС      │───▶│    ВЫХОДЫ    │
│              │    │                         │    │              │
│ • Информация │    │  (преобразование входов  │    │ • Продукт    │
│ • Документы  │    │   в выходы, создающие    │    │ • Услуга     │
│ • Ресурсы    │    │   ценность для           │    │ • Документ   │
│ • Заявки     │    │   потребителя)           │    │ • Результат  │
│              │    │                         │    │              │
└──────────────┘    └────────────┬────────────┘    └──────────────┘
                                 │
                                 ▲
┌────────────────────────────────┴────────────────────────────────┐
│                         МЕХАНИЗМЫ (РЕСУРСЫ)                      │
│     (персонал, оборудование, ПО, финансы, помещения)             │
└─────────────────────────────────────────────────────────────────┘
```

**Пояснение:** Схема отражает классическую структуру бизнес-процесса в нотации IDEF0. Стрелки сверху — это управляющие воздействия (правила и ограничения). Стрелки снизу — механизмы, то есть ресурсы, которые обеспечивают выполнение процесса. Слева — входы (что поступает в процесс), справа — выходы (что получает потребитель) [10, 13].

## Таблица 4. Этапы жизненного цикла бизнес-процесса

| № | Этап | Что происходит | Результат | Инструменты |
|---|---|---|---|---|
| 1 | Проектирование | Определяются цели, структура, участники, ресурсы | Концепция процесса | Интервью, мозговой штурм, бенчмаркинг |
| 2 | Моделирование | Создаётся графическое описание логики процесса | Модель «как есть» (AS-IS) и «как должно быть» (TO-BE) | BPMN, IDEF0, EPC, DFD |
| 3 | Внедрение | Разрабатываются регламенты, обучается персонал | Запущенный процесс | Регламенты, инструкции, ИС |
| 4 | Выполнение | Процесс работает по установленным правилам | Продукт/услуга | ERP, LMS, СЭД |
| 5 | Мониторинг | Собираются данные о ходе выполнения | Метрики и отчёты | Дашборды, KPI, BI-системы |
| 6 | Анализ | Выявляются узкие места, отклонения, проблемы | Список проблем и рекомендаций | Process Mining, ABC-анализ |
| 7 | Оптимизация | Вносятся изменения для повышения эффективности | Улучшенный процесс | Lean, Six Sigma, автоматизация |

## Таблица 6. Сравнительная характеристика нотаций моделирования бизнес-процессов

| Критерий | IDEF0 | IDEF3 | BPMN | EPC |
|---|---|---|---|---|
| **Разработчик / стандарт** | ICAM, США (FIPS 183) | Knowledge Based Systems Inc. | Object Management Group (OMG) | A.-W. Scheer, концепция ARIS |
| **Базовая идея** | Функциональная декомпозиция | Поток работ и смена состояний | Графическое описание потоков операций | Чередование событий и функций |
| **Основные элементы** | Функциональный блок, стрелки ICOM (вход, выход, управление, механизм) | Единицы работы (UOW), связи, перекрёстки (junctions) | События, операции (задачи), шлюзы, потоки, дорожки | События, функции, логические операторы (AND/OR/XOR), орг. единицы |
| **Тип представления** | Иерархический, статический | Логика и временная последовательность | Потоковый, многоуровневый | Сетевой, событийно-ориентированный |
| **Возможность исполнения** | Нет (описательная) | Нет (описательная) | Да (BPMN 2.0 исполняется в BPMS) | Частично (в ARIS/SAP Solution Manager) |
| **Поддержка ветвлений** | Ограниченная | Развитая (XOR, OR, AND) | Полная (8 типов шлюзов) | Полная (через логические операторы) |
| **Уровень сложности восприятия** | Низкий | Средний | Средний (от простого к сложному) | Средний |
| **Типичная область применения** | Функциональное обследование «as-is» | Моделирование логики и сценариев | Автоматизация и регламентация процессов | Комплексное описание в ERP/ARIS |
| **Распространённость в РФ** | Высокая (унаследовано из 1990-х) | Низкая | Растущая (де-факто стандарт) | Средняя (вместе с SAP и ARIS) |

## Рисунок 4. Базовые элементы нотации BPMN

```
┌──────────────────────────────────────────────────────────────────────┐
│                     ОБЪЕКТЫ ПОТОКА (Flow Objects)                     │
├────────────────────────┬──────────────────────┬──────────────────────┤
│                        │                      │                      │
│   СОБЫТИЯ              │   ОПЕРАЦИИ           │   ШЛЮЗЫ              │
│                        │                      │                      │
│    ○  начальное        │   ┌─────────┐        │    ◇   эксклюзивный  │
│                        │   │  Задача │        │                      │
│    ◉  промежуточное    │   └─────────┘        │    ◈   параллельный  │
│                        │                      │        (AND)         │
│    ●  конечное         │   ┌─────────┐        │                      │
│                        │   │⊞ Подпр-сс│       │    ◉   включающий    │
│                        │   └─────────┘        │        (OR)          │
│                        │                      │                      │
├────────────────────────┴──────────────────────┴──────────────────────┤
│                   СОЕДИНИТЕЛЬНЫЕ ОБЪЕКТЫ (Connectors)                 │
├──────────────────────────────────────────────────────────────────────┤
│                                                                      │
│   ──▶    поток последовательности (Sequence Flow)                   │
│   ╌╌▶    поток сообщений (Message Flow)                              │
│   ┄┄┄    ассоциация (Association)                                    │
│                                                                      │
├──────────────────────────────────────────────────────────────────────┤
│                      ДОРОЖКИ (Swimlanes)                              │
├──────────────────────────────────────────────────────────────────────┤
│                                                                      │
│   ┌──────────────────────────────────────────────────┐              │
│   │  Пул (Pool): организация / участник процесса     │              │
│   ├──────────────────────────────────────────────────┤              │
│   │  Дорожка (Lane): подразделение / роль            │              │
│   └──────────────────────────────────────────────────┘              │
│                                                                      │
├──────────────────────────────────────────────────────────────────────┤
│                       АРТЕФАКТЫ (Artifacts)                           │
├──────────────────────────────────────────────────────────────────────┤
│                                                                      │
│   ▢  объект данных      [ ]  группа       ✎  текстовая аннотация    │
│                                                                      │
└──────────────────────────────────────────────────────────────────────┘
```

**Пояснение:** Схема обобщает четыре категории элементов нотации BPMN 2.0. Объекты потока (события, операции, шлюзы) формируют скелет модели. Соединительные объекты задают логику взаимодействия. Дорожки распределяют ответственность между участниками. Артефакты несут пояснительную нагрузку. Такое разделение позволяет использовать BPMN как для высокоуровневого описания, понятного бизнес-пользователям, так и для создания исполняемых моделей для систем BPMS [59; 60, с. 89; 64].

## Рисунок 5. Фрагмент EPC-диаграммы процесса «Приём заявления абитуриента»

```
              ┌──────────────────────────┐
              │  Поступило заявление     │   ← событие (E)
              │  от абитуриента          │
              └────────────┬─────────────┘
                           │
                           ▼
              ╔══════════════════════════╗
              ║  Проверить комплектность ║   ← функция (F)
              ║  документов              ║
              ╚════════════┬═════════════╝
                           │
                           ▼
                          ◇ XOR                 ← логический оператор
                   ┌───────┴────────┐
                   ▼                ▼
      ┌─────────────────┐  ┌─────────────────┐
      │ Документы       │  │ Документы       │  ← события (E)
      │ полные          │  │ неполные        │
      └────────┬────────┘  └────────┬────────┘
               │                    │
               ▼                    ▼
      ╔════════════════╗   ╔════════════════╗
      ║ Зарегистриро-  ║   ║ Запросить      ║  ← функции (F)
      ║ вать заявление ║   ║ недостающие    ║
      ╚════════┬═══════╝   ╚════════════════╝
               │
               ▼
      ┌─────────────────┐
      │ Заявление       │                       ← событие (E)
      │ зарегистрировано│
      └─────────────────┘

  Легенда:  ┌─┐ событие (E)   ╔═╗ функция (F)   ◇ логический оператор
```

**Пояснение:** Диаграмма иллюстрирует ключевой принцип нотации EPC — обязательное чередование событий и функций. Каждая функция инициируется событием и завершается событием. Логические операторы (XOR, AND, OR) управляют ветвлением и синхронизацией потока. Благодаря явному выделению событий EPC хорошо подходит для описания процессов со сложной условной логикой и интеграции с ERP-системами [58; 62].

## Таблица 7. Сравнение подходов к имитационному моделированию бизнес-процессов

| Признак | Дискретно-событийное моделирование | Системная динамика | Агентное моделирование |
|---|---|---|---|
| **Основная единица** | Событие, изменяющее состояние системы | Уровень (запас), поток, обратная связь | Автономный агент со своим поведением |
| **Уровень абстракции** | Средний | Высокий (стратегический) | Низкий–средний (индивидуальное поведение) |
| **Время в модели** | Дискретные моменты наступления событий | Непрерывное | Дискретное или непрерывное |
| **Что моделируют** | Очереди, обслуживание, конвейеры | Долгосрочные тенденции, петли причинности | Взаимодействие множества сущностей |
| **Применение в образовании** | Поток документов, расписание, сессия, приёмная кампания | Развитие вуза, динамика контингента студентов | Поведение абитуриентов, траектории студентов |
| **Типичные инструменты** | AnyLogic, Arena, Simio, ExtendSim | Vensim, Stella, AnyLogic | AnyLogic, NetLogo, Repast |
| **Требуемые данные** | Распределения длительностей, интенсивности заявок | Агрегированные показатели, коэффициенты | Правила поведения агентов, параметры окружения |
| **Основное преимущество** | Детальный анализ операционной эффективности | Учёт долгосрочных обратных связей | Учёт гетерогенности участников |
| **Основное ограничение** | Трудоёмкость сбора исходных данных | Сложность калибровки | Высокая вычислительная сложность |

## Таблица 8. Восемь видов потерь в концепции бережливого производства и их проявление в образовательной организации

| № | Вид потерь (по Lean) | Суть потерь | Типичные проявления в вузе |
|---|---|---|---|
| 1 | **Перепроизводство** | Создание того, что не востребовано | Разработка методических материалов, не используемых в учебном процессе; избыточное количество отчётов |
| 2 | **Ожидание** | Простои, задержки | Очереди в деканате, ожидание согласования приказов, задержки при получении справок |
| 3 | **Лишняя транспортировка** | Ненужные перемещения материалов/документов | Доставка бумажных документов между корпусами; многократная пересылка файлов между подразделениями |
| 4 | **Излишняя обработка** | Действия, не добавляющие ценности | Повторный ввод одних и тех же данных в разные системы; дублирующие согласования |
| 5 | **Избыточные запасы** | Накопление ненужного | Устаревшая литература в библиотеке; избыточные запасы канцелярии; неиспользуемое ПО |
| 6 | **Лишние движения** | Неэффективные действия работников | Поиск документов в разрозненных папках; хождение сотрудников между кабинетами для подписи |
| 7 | **Дефекты** | Ошибки, брак, переделки | Ошибки в приказах, дипломах, расписании; повторное оформление документов |
| 8 | **Нереализованный потенциал сотрудников** | Неиспользование компетенций персонала | Загрузка преподавателей рутинными задачами; слабое вовлечение ППС в проектную деятельность |

*Составлено на основе [57; 78]*
